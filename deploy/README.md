# Рассылка на Ubuntu

Разместите репозиторий в постоянном каталоге, доступном на запись непривилегированному пользователю рассылки. Установите системные пакеты `python3`, `python3-venv` и `tzdata`. Подготовьте проект из его корневого каталога от имени этого пользователя.

```sh
umask 077
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
test -e .env || cp .env.example .env
```

Заполните SMTP-настройки в локальном `.env`. При наличии прежней переменной `RECIPIENTS` выполните `.venv/bin/python recipients.py migrate`. Для нового списка используйте `.venv/bin/python recipients.py add EMAIL`, подставив нужный адрес.

```sh
sudo bash deploy/install.sh
mailer status
```

Установка использует учётную запись, вызвавшую `sudo`. При установке из root-сеанса укажите пользователя через `--user ИМЯ`. Установщик проверяет окружение и конфигурацию, ограничивает доступ к локальным файлам режимом `0600` и регистрирует юниты. Содержимое `.env`, списка адресатов и истории сохраняется. Повторная установка сохраняет текущее состояние таймера. Новая установка оставляет таймер выключенным.

## Запуск и управление

Команда `mailer` доступна из любой директории. Отправка, просмотр истории и управление адресатами выполняются от имени пользователя рассылки с тем же рабочим каталогом, что и у сервиса. При запуске от другой учётной записи команда может потребовать `sudo`.

- `mailer enable` включает расписание и запуск после перезагрузки. Из-за `Persistent=true` включение таймера может сразу запустить пропущенную рассылку.
- `mailer disable` отключает расписание. Уже начатая рассылка продолжится.
- `mailer next` показывает следующий запуск по Москве. `mailer status` показывает состояние юнитов. Сервис `oneshot` обычно неактивен между запусками.
- `mailer send` вручную запускает рассылку за предыдущую завершённую неделю. Для другого периода укажите `--start-date YYYY-MM-DD --end-date YYYY-MM-DD`.
- `mailer history` показывает уже обработанные периоды. Используйте `mailer send --force` после ручной проверки доставки, когда действительно нужна повторная отправка.
- `mailer logs` показывает последние записи сервиса, таймера и ручных запусков. Для чтения системного журнала при необходимости используйте `sudo mailer logs`.
- `mailer help` перечисляет все команды, включая управление адресатами.

Таймер срабатывает в понедельник в 09:00 по Москве. После простоя он компенсирует пропуски одним запуском. Программа при этом выбирает неделю, завершившуюся к моменту фактического запуска. Более ранние пропущенные недели отправляются вручную с явными датами. Ошибка SMTP сама по себе повторной отправки не запускает.

## Проверки на сервере

Проверить синтаксис и календарь можно без запуска рассылки.

```sh
bash -n deploy/install.sh
bash -n deploy/mailer
systemd-analyze calendar 'Mon *-*-* 09:00:00 Europe/Moscow'
systemd-analyze verify /etc/systemd/system/gov-mailer.service /etc/systemd/system/gov-mailer.timer
```

Проверка установленного таймера после включения и после перезагрузки выполняется через `mailer status` и `mailer next`.
