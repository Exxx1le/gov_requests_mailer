# gov_requests_mailer

## 1. Назначение

`gov_requests_mailer` собирает нормативные правовые акты с портала официального опубликования правовых актов и формирует подборку в Word. Документы группируются по органам, указанным в [`constants.py`](constants.py). В подборку входят названия, даты и ссылки на публикации. Программа прикладывает DOCX к письму и отправляет его настроенным адресатам через SMTP с TLS.

Администратор может запустить рассылку по расписанию или за выбранный период, управлять адресатами, смотреть журнал попыток и проверять результаты в системном журнале.

## 2. Еженедельная рассылка

Таймер `gov-mailer.timer` запускает `gov-mailer.service` каждый понедельник в **09:00 по Москве (`Europe/Moscow`)**. Программа выбирает предыдущую завершённую календарную неделю с понедельника по воскресенье включительно. Например, запуск в понедельник 30 ноября 2026 года выбирает 23–29 ноября.

**После `mailer enable` рассылка работает автоматически. Еженедельно выполнять `mailer send` не требуется.** Настройка сохраняется при перезагрузке. Сервис работает в режиме `oneshot`, поэтому состояние `inactive (dead)` между успешными запусками нормально. У включённого таймера ожидается состояние `active (waiting)` между срабатываниями.

При `Persistent=true` systemd может запустить сервис сразу после активации таймера, если во время простоя было пропущено хотя бы одно срабатывание. Это один компенсирующий запуск за неделю, завершившуюся к моменту фактического старта. Остальные пропущенные недели обработайте вручную по [порядку восстановления](#vosstanovlenie-periodov). [Документация systemd.timer](https://www.freedesktop.org/software/systemd/man/latest/systemd.timer.html)

## 3. Системные требования

- Ubuntu Server с systemd в качестве системного менеджера, например Ubuntu 24.04 LTS. На сервере должны быть настроены системное время и база часовых поясов.
- Python 3.10 или новее, `python3-venv`, Git и пакет `ca-certificates`. Python-зависимости перечислены в [`requirements.txt`](requirements.txt).
- Непривилегированная учётная запись, которой доступны на запись постоянный каталог проекта и `generated/`. Для установки юнитов и управления таймером нужны права администратора.
- Исходящий доступ к GitHub и PyPI при установке и обновлении. Для рассылки нужен доступ к `publication.pravo.gov.ru` по HTTP и к SMTP-серверу по TLS на настроенном порту. Для Яндекс Почты используется `smtp.yandex.ru:465`. [Настройка клиента Яндекс Почты](https://www.yandex.ru/support/yandex-360/customers/mail/ru/mail-clients/others)

## 4. Установка на чистый Ubuntu-сервер

1. Войдите под обычным пользователем Ubuntu с доступом к `sudo`. В этом примере он будет владельцем проекта и пользователем рассылки. Установите пакеты.

   ```bash
   sudo apt update
   sudo apt install git python3 python3-venv tzdata ca-certificates nano
   ```

2. Клонируйте репозиторий в постоянный каталог и установите Python-зависимости от имени пользователя рассылки.

   ```bash
   cd "$HOME"
   git clone https://github.com/Exxx1le/gov_requests_mailer.git
   cd gov_requests_mailer
   umask 077
   python3 -m venv .venv
   .venv/bin/python -m pip install -r requirements.txt
   .venv/bin/python -m pip check
   ```

3. Создайте локальный `.env` из шаблона, если файла ещё нет.

   ```bash
   test -e .env || cp -- .env.example .env
   chmod 600 .env
   nano .env
   ```

   В шаблоне предусмотрены четыре параметра.

   | Параметр | Значение |
   | --- | --- |
   | `EMAIL_HOST` | Имя SMTP-сервера, по умолчанию `smtp.yandex.ru`. |
   | `EMAIL_PORT` | Порт SMTP с TLS при подключении, по умолчанию `465`. |
   | `EMAIL_USER` | Полный адрес почтового ящика отправителя. |
   | `EMAIL_PASSWORD` | SMTP-пароль. Для Яндекс Почты используйте пароль приложения. [Инструкция Яндекс Почты](https://www.yandex.ru/support/yandex-360/customers/mail/ru/mail-clients/others) |

4. Добавьте хотя бы одного адресата. Подставьте нужный адрес вместо учебного.

   ```bash
   .venv/bin/python recipients.py add recipient@example.com
   .venv/bin/python recipients.py count
   ```

   При переносе прежней конфигурации с `RECIPIENTS` вместо первого `add` используйте `.venv/bin/python recipients.py migrate`. Миграция создаёт `recipients.json` только при отсутствии файла. В дальнейшем адресаты читаются из `recipients.json` в корне проекта.

5. Установите systemd-юниты и глобальную команду `mailer`.

   ```bash
   sudo bash deploy/install.sh
   mailer help
   mailer status
   ```

   Установщик определяет абсолютный путь к проекту и пользователя, вызвавшего `sudo`. Для отдельной сервисной учётной записи подготовьте проект и локальные данные от её имени, затем из корня проекта запустите `sudo bash deploy/install.sh --user govmailer`. Подставьте имя существующей учётной записи. Код рассылки выполняется от этого пользователя, в том числе при запуске `mailer send` администратором.

   Установщик проверяет виртуальное окружение, зависимости, настройки SMTP и наличие адресатов. Для локальных файлов конфигурации и истории он устанавливает режим `0600` и сохраняет их содержимое. После первой установки таймер ожидает явного включения. Повторная установка сохраняет его текущее состояние.

## 5. Включение и отключение расписания

```bash
mailer enable
mailer status
mailer next
```

`mailer enable` активирует таймер сразу и при последующих загрузках Ubuntu. Если systemd обнаружит пропущенное срабатывание, первая отправка может начаться сразу после включения. Права администратора при необходимости запрашиваются через `sudo`.

```bash
mailer disable
mailer status
```

`mailer disable` останавливает таймер и отменяет его запуск при загрузке. Уже начатая отправка продолжится. Ручные команды и история доступны при выключенном таймере.

## 6. Справочник команд `mailer`

После установки команды доступны из любой директории. Отправка, изменение адресатов и просмотр истории используют один рабочий каталог и учётную запись пользователя рассылки. Запуск из другой учётной записи может потребовать `sudo`.

### Расписание и состояние

- `mailer enable` включает расписание и запускает таймер.
- `mailer disable` останавливает таймер и убирает его из автозапуска.
- `mailer status` показывает состояния обоих юнитов и недавние сообщения systemd. Ненулевой код этой команды возможен, когда один из юнитов неактивен. Результат последней отправки смотрите в журнале и истории.
- `mailer next` показывает следующее запланированное срабатывание по московскому времени. При выключенном таймере выводится сообщение об отсутствии запланированного запуска.

```bash
mailer status
mailer next
```

### Ручная отправка

- `mailer send` обрабатывает предыдущую завершённую неделю по Москве.
- `mailer send --force` принудительно отправляет подборку за предыдущую завершённую неделю.
- `mailer send --start-date YYYY-MM-DD --end-date YYYY-MM-DD` обрабатывает заданный период. Обе даты обязательны, границы включаются. Начальная дата должна быть раньше конечной или совпадать с ней.
- `mailer send --start-date YYYY-MM-DD --end-date YYYY-MM-DD --force` принудительно отправляет заданный период.

```bash
mailer send
mailer send --force
mailer send --start-date 2026-11-16 --end-date 2026-11-22
mailer send --start-date 2026-11-16 --end-date 2026-11-22 --force
```

Обычная команда пропускает точный период с кодом `0`, когда последняя запись со статусом, отличным от `failed`, имеет статус `sent`. Пересекающиеся диапазоны с разными границами считаются разными периодами. **`--force` может повторно доставить письмо адресатам, которые уже его получили.** Перед принудительной отправкой сверяйте историю и подтверждения доставки. У ручного запуска вывод уходит в системный журнал, код завершения остаётся доступен вызывающей оболочке.

### Адресаты

- `mailer list` показывает адреса из локального `recipients.json`.
- `mailer add EMAIL` добавляет адрес. Дубликаты отклоняются без учёта регистра.
- `mailer remove EMAIL` удаляет адрес. Для отсутствующего адреса выводится ошибка.
- `mailer count` выводит количество адресатов.
- `mailer migrate` переносит адреса из прежнего `RECIPIENTS`. Одноимённая переменная окружения имеет приоритет перед записью в `.env`. При наличии `recipients.json` команда прекращает перенос, сохраняя оба файла.

```bash
mailer add recipient@example.com
mailer count
mailer list
mailer remove recipient@example.com
# При переносе со старой версии и отсутствии recipients.json
mailer migrate
```

### История, журнал и справка

- `mailer history` показывает периоды, время попыток в UTC и статусы по-русски.
- `mailer logs` показывает до 100 последних записей таймера, сервиса и ручной отправки. Если у текущего пользователя ограничен доступ к системному журналу, используйте `sudo mailer logs`.
- `mailer help` показывает русскоязычную справку.

```bash
mailer history
mailer logs
mailer help
```

## 7. История рассылок и восстановление

История хранится в локальном `mailing_history.json`. В каждой записи есть границы периода, отметка времени и статус. Запись выполняется атомарно, а ручной и автоматический процессы используют одну межпроцессную блокировку. Повреждённая история останавливает отправку даже при `--force`. Сохраните повреждённый файл для диагностики и восстановите проверенную копию.

| Статус | Что означает и что делать |
| --- | --- |
| `pending` | Запись сохранена перед подключением к SMTP. Если она осталась после завершения процесса, результат требует ручной проверки. Обычный повтор блокируется. |
| `sent` | SMTP подтвердил приём для всех адресатов. Программа сохраняет этот статус до удаления DOCX и пропускает обычный повтор точного периода. Доставку в почтовые ящики проверяют отдельно. |
| `failed` | Программа установила, что отправка не состоялась. Например, произошёл сбой API, проверка адресатов завершилась ошибкой или SMTP явно отклонил письмо. Устраните причину, затем повторите отправку за тот же период. |
| `uncertain` | Часть адресатов отклонена или результат передачи неизвестен, например из-за обрыва связи во время отправки. Обычный повтор блокируется. Сначала выясните, кто получил письмо. |

<a id="vosstanovlenie-periodov"></a>
### Порядок восстановления пропущенных периодов

1. Откройте `mailer history` и `mailer logs`. Сопоставьте точные границы недель с фактическими отправками, включая компенсирующий запуск systemd.
2. За каждый действительно пропущенный период выполните отдельный запуск с явными датами, начиная с самой ранней недели. Используйте обычную отправку для отсутствующей записи или подтверждённого сбоя.

   ```bash
   mailer send --start-date 2026-11-09 --end-date 2026-11-15
   mailer history
   ```

3. Для `pending` или `uncertain` проверьте доставку по журналам SMTP-провайдера или у адресатов. Если повтор всей рассылки оправдан, укажите тот же период и `--force`. При частичной доставке учитывайте, что уже получившие письмо адресаты могут получить его повторно.

Ошибки SMTP сами по себе не запускают автоматическую повторную отправку. Сервис настроен на один запуск без перезапуска при ошибке.

## 8. Удаление Word-файлов

Подборки создаются в `generated/` в формате DOCX. При запуске новой рассылки после проверки истории и адресатов программа удаляет DOCX из верхнего уровня этого каталога, если с момента их последнего изменения прошло более семи суток.

Текущий файл удаляется после того, как SMTP-сервер подтвердит приём письма для всех адресатов и программа запишет `sent` в историю. При сбое SMTP DOCX остаётся на сервере и может позднее попасть под семидневную очистку. При ошибке удаления после отправки статус сохраняется как `sent`, а подробности появляются в журнале. Если нужен сам документ, скопируйте его в отдельный каталог хранения до очередной очистки.

## 9. Журналы и диагностика

```bash
mailer status
mailer next
mailer logs
sudo journalctl -u gov-mailer.service -u gov-mailer.timer --since today --no-pager
sudo journalctl -t gov-mailer --since today --no-pager
systemctl show gov-mailer.service -p ActiveState -p Result -p ExecMainStatus
```

| Симптом | Что проверить |
| --- | --- |
| `inactive (dead)` у сервиса | Для `oneshot` между запусками это штатное состояние. Смотрите `Result`, журнал последней попытки и активность таймера. |
| Следующего запуска нет | Проверьте, установлен ли таймер и выполнено ли `mailer enable`. Сверьте часы сервера и результат `mailer next`. |
| Ошибка получения документов | Проверьте DNS и доступ к порталу с сервера. После исчерпания попыток запроса письмо не отправляется. Сверьте статус периода перед ручным запуском. |
| Получателей нет или JSON повреждён | Проверьте `mailer count`, права доступа и содержимое `recipients.json`. При повреждении восстановите резервную копию или исправьте файл вне активного запуска. |
| Ошибка SMTP | Проверьте имя сервера, порт TLS, доступ к нему из сети Ubuntu, адрес отправителя и пароль приложения. При неопределённом результате начните с [проверки доставки](#vosstanovlenie-periodov). |
| Ошибка записи истории или удаления DOCX | Проверьте владельца локальных файлов, права на запись в проект и `generated/`, а также свободное место. Для отправленного письма ориентируйтесь на историю и подтверждение SMTP перед любым повтором. |

Код ручной отправки `0` означает успех или пропуск уже отправленного периода. Код `1` означает ошибку выполнения либо блокировку из-за неизвестного результата предыдущей попытки. Код `2` означает ошибку в аргументах.

Команды ниже проверяют shell-синтаксис, календарь и установленные юниты без запуска рассылки. Проверяйте переход таймера в ожидание и восстановление расписания после перезагрузки отдельно на целевом Ubuntu-сервере.

```bash
bash -n deploy/install.sh
bash -n deploy/mailer
systemd-analyze calendar 'Mon *-*-* 09:00:00 Europe/Moscow'
systemd-analyze verify /etc/systemd/system/gov-mailer.service /etc/systemd/system/gov-mailer.timer
```

## 10. Обновление из GitHub

1. Зафиксируйте, включён ли таймер, командой `systemctl is-enabled gov-mailer.timer`. Если он включён, временно выполните `mailer disable` и дождитесь завершения текущей рассылки. На время обновления остановите ручные запуски.
2. Сделайте [резервную копию локальных файлов](#backup). Обновляйте репозиторий от имени пользователя рассылки.

   ```bash
   cd "$HOME/gov_requests_mailer"
   git status --short
   git switch main && git pull --ff-only origin main
   ```

   Если Git сообщает о локальных изменениях или расхождении веток, разберите их перед продолжением. Например, очистка может удалить ранее добавленный в Git пример DOCX из `generated/`, и Git отметит это удаление. `.env`, `recipients.json` и `mailing_history.json` исключены из Git. Избегайте `git clean -fdx`, удаляющей также игнорируемые файлы.

3. После успешного обновления установите зависимости и перерегистрируйте юниты и команду `mailer`.

   ```bash
   .venv/bin/python -m pip install -r requirements.txt && sudo bash deploy/install.sh
   ```

   Для выделенной сервисной учётной записи используйте тот же `--user`, что при первоначальной установке.
4. Проверьте `mailer count`, `mailer history` и `mailer status`. Если таймер был включён до обслуживания, выполните `mailer enable` и `mailer next`. Учитывайте возможный компенсирующий запуск после включения.

## 11. Резервное копирование

Копируйте `.env`, `recipients.json` и `mailing_history.json`, если он уже существует. Делайте копию от имени пользователя рассылки при остановленном таймере, после завершения текущей отправки и вне ручных изменений адресатов.

```bash
(
    set -eu
    umask 077
    cd "$HOME/gov_requests_mailer"
    backup_dir="$HOME/.local/state/gov-mailer/backups"
    install -d -m 0700 "$backup_dir"
    archive=$(mktemp --suffix=.tar.gz "$backup_dir/gov-mailer-XXXXXXXX")
    files=(.env recipients.json)
    if [[ -f mailing_history.json ]]; then
        files+=(mailing_history.json)
    fi
    tar -czf "$archive" -- "${files[@]}"
    tar -tzf "$archive"
    printf 'Резервная копия: %s\n' "$archive"
)
```

Храните архив как секрет, поскольку он содержит SMTP-пароль и список адресатов. Для восстановления выключите таймер, дождитесь окончания отправки и сохраните копию текущих файлов. Распакуйте проверенный архив в отдельный закрытый каталог от имени пользователя рассылки. Перенесите нужные файлы в корень проекта с правами `0600` и проверьте `mailer count` и `mailer history` до включения таймера. При восстановлении старой истории сверьте отправки после даты резервной копии с журналами, чтобы не отправить их повторно.

## 12. Безопасность

- Храните SMTP-пароль в локальном `.env`. Используйте пароль приложения и меняйте его при подозрении на утечку.
- Ограничьте доступ к `.env`, `recipients.json`, `mailing_history.json` и резервным копиям режимом `0600`. Для каталога резервных копий используйте `0700`.
- Добавляйте адресатов с учётом того, что в письме они видят список адресов в поле `To`.
- Выполняйте операции над данными от имени пользователя рассылки. Используйте административные права для установки, управления таймером и чтения системного журнала по необходимости.
- Сохраняйте файлы блокировок рядом с проектом. Удаление файла блокировки во время работы может нарушить защиту от одновременных запусков.
- Исключайте реальные пароли, адреса и историю из коммитов, отчётов об ошибках и публичных журналов. Проверяйте вывод `git status --short` перед отправкой изменений.

## 13. Структура проекта

| Путь | Назначение |

| `main.py` | Выбор периода, запуск сборки, почтовой отправки и очистки. |

| `test_*.py` | Автоматические тесты рассылки, API, SMTP, очистки, адресатов и истории. |

## 14. Автоматические тесты

Выполните из корня проекта после установки зависимостей.

```bash
.venv/bin/python -B -m unittest discover -v
```

Тесты подменяют обращения к API и SMTP и используют временные файлы. Для проверки systemd на Ubuntu используйте команды из раздела диагностики. Проверка приложения тестами и проверка активного таймера после перезагрузки выполняются отдельно.

## 15. Шпаргалка администратора

| Команда | Действие |
| --- | --- |
| `mailer enable` | Включить расписание и автозапуск таймера. |
| `mailer disable` | Остановить таймер и отключить его автозапуск. |
| `mailer status` | Посмотреть состояния сервиса и таймера. |
| `mailer next` | Узнать время следующего запуска по Москве. |
| `mailer send` | Отправить подборку за предыдущую завершённую неделю. |
| `mailer send --force` | Повторно отправить подборку за предыдущую завершённую неделю. |
| `mailer send --start-date YYYY-MM-DD --end-date YYYY-MM-DD` | Отправить подборку за указанные даты включительно. |
| `mailer send --start-date YYYY-MM-DD --end-date YYYY-MM-DD --force` | Принудительно отправить подборку за указанный период. |
| `mailer list` | Посмотреть список адресатов. |
| `mailer add EMAIL` | Добавить адресата. |
| `mailer remove EMAIL` | Удалить адресата. |
| `mailer count` | Узнать число адресатов. |
| `mailer migrate` | Однократно перенести прежний список из `RECIPIENTS`. |
| `mailer history` | Посмотреть историю попыток. |
| `mailer logs` | Посмотреть недавние записи системного журнала. |
| `mailer help` | Открыть справку. |
